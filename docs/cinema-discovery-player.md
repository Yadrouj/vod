# Cinema landing, discovery and player

The film landing uses full-width artwork, portrait art on narrow screens, an eight-second carousel, pause/navigation controls and search. Hover, focus, hidden tabs and reduced-motion preferences pause automatic movement. Film and series picks share the hero.

Recommendations combine catalog IMDb ratings and vote counts, recent IMDb popularity, and SarvNema audience feedback. The confidence-adjusted rating is an internal SarvNema ranking score, not a replacement IMDb rating. Genre/title relevance remains mandatory on a title's suggestions tab. Titles without download/playback links are excluded. New feedback influences the next uncached calculation: data is cached for 30 seconds; suggestion responses have a five-minute shared cache plus up to five minutes of stale-while-revalidate.

`npm run refresh-imdb-trending` is already part of the daily maintenance job. It now keeps up to 100 matches per chart and extracts ratings/vote totals when provided by the chart. A challenge, denied request or malformed chart retains the last good snapshot. Popularity boosts expire after eight days; old snapshots are never presented as current trends. This does not bypass IMDb access restrictions. IMDb review text is not imported: no review feed is configured. The comments used here are explicitly submitted SarvNema feedback, not IMDb comments, and their text is not treated as inferred sentiment.

The Suggestions tab offers Yes/Not really feedback with an optional private 500-character comment. Explicit votes influence sentiment; comment counts provide a small, bounded interest signal. The API validates origin/title/body size, rate limits submissions and replaces the same client/title ballot. IP and user-agent are HMAC-hashed with a private local key; raw values are not stored. This is a lightweight anonymous signal, not verified accounts or a fraud-proof voting service. Text is never exposed by a public endpoint. Records expire from scoring at 30 days and are pruned on writes; the store is capped at 5,000 ballots.

Keep `data/discovery/` writable and persistent (the existing Docker `./data:/app/data` mount covers it). It is ignored by Git. `DISCOVERY_DATA_DIR` may override its location; keep it outside public/. Configure `NEXT_PUBLIC_SITE_URL` or `SITE_URL` to the public HTTPS origin (default `https://sarvnema.ir`) so same-site feedback works behind the reverse proxy. A cross-process file lock protects writes. After an abnormal process termination, remove `write.lock` only after confirming no writer is active. Deploy replicas against a shared persistent directory or replace this small file store with a database. Backups containing feedback should be access restricted.

The video player loads a default source, preserves time across quality changes of the same episode, and resumes other episodes from their own saved progress. Settings are a compact desktop panel and a full-screen mobile dialog. Episode selection remains available from the list icon. Controls include a buffered scrubber, next episode, captions, fullscreen and volume; casting and picture-in-picture are in Settings. Hover preview shows time, not a fabricated video frame.

Shortcuts: Space/K play or pause, J/L seek ten seconds, arrows seek five seconds, up/down adjust volume, 0–9 seek by percentage, M mute, F fullscreen. Typing in forms is excluded. Double-click toggles desktop fullscreen; double-tap on the left/right half seeks on touch devices. Screen rotation remains best-effort through the existing fullscreen helper because browser support varies. External publishers' embedded players retain their own controls.

Verification: `node --import tsx --test scripts/tests/discovery-ranking.test.ts`, `node --test scripts/tests/imdb-charts.test.mjs`, TypeScript, production build, and browser checks at desktop/mobile widths with local media fixtures.

Browser regression: start the server with `DISCOVERY_DATA_DIR=.media-cache/feedback-smoke`, then run `node scripts/smoke-cinema-redesign.mjs`. Set `LOAD_BASE_URL` for the local test port and `PLAYWRIGHT_MODULE` to an installed Playwright module path if it is not locally resolvable. It uses Chrome, blocks real media downloads with a local 180-second fixture, exercises playback/seek/mute/fullscreen/quality switching, checks 320px/390px and Persian RTL panels, and submits feedback only to the local test store. Screenshots are written under ignored `.media-cache/`.
